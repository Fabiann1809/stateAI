# Architecture

[Español](../architecture.md) · **English**

## Modules and dependencies

```
app-wear ──► core-domain ◄── data
   │              ▲   ▲
   ├──► sensors ──┘   │
   ├──► haptics ──────┘
   └──► data
```

| Module | Responsibility | Android |
|---|---|---|
| `core-domain` | Models, rules, learning, scoring and the interfaces the domain needs (`ActivityRepository`, `SegmentRepository`, `BaselineRepository`, `SensorSource`, `HapticPlayer`). | No |
| `sensors` | `SimulatedSensorSource` (scripted scenarios) and `HealthServicesSensorSource`. | Yes |
| `haptics` | Waveforms and `VibratorHapticPlayer`. | Yes |
| `data` | Room and DataStore implementations behind `LocalStorage`, which only exposes domain interfaces. | Yes |
| `ml` | `TfLiteLevelModel`: wrapper for the TFLite classifier trained on synthetic data (Phase 7). If it fails, the app falls back to the rule-based classifier. | Yes |
| `shared` | Data generated by `ml-python` (parity cases and cycle traces) that the Kotlin tests read to check that both sides agree. | No |
| `app-wear` | Compose UI, ViewModels, the foreground session service, voice input and the `AppContainer` (manual dependency injection, split into modules: sensors, haptics, classifier, insights). | Yes |

Rules:

- `core-domain` imports nothing from Android and all of its behavior has JVM unit tests.
- The domain owns the interfaces it consumes (dependency inversion). The implementations live in the
  Android modules and are wired together in `AppContainer`.
- Domain tests use in-memory doubles (`core-domain/src/test/.../testing`); `data` provides
  `InMemoryActivityRepository` and `InMemorySegmentRepository` for the app's tests.
- Storage keeps only summaries, never the raw signal.

## Session flow

```
SensorSource ─► BaselineKeeper (first use: 2-minute calibration, stored in DataStore)
             └► FeatureWindowStream (3-minute window every 60 s)
                  └► StateEngine (clean-window filter → RuleBasedClassifier → StateSmoother)
                       ├► MonitorStatus ─► session screen
                       ├► SegmentRecorder (time per level, pauses) ─► EndSession ─► SegmentRepository
                       └► HapticPolicy ─► RateLimitedHapticPlayer ─► VibratorHapticPlayer
```

`SessionService` (foreground, with an Ongoing Activity) runs `SessionMonitor` while a session is
active, so the estimation continues with the screen off.

## Repositories

| Interface | Implementation | Notes |
|---|---|---|
| `ActivityRepository` | `RoomActivityRepository` | Sorted by last use; key = category + normalized name. |
| `SegmentRepository` | `RoomSegmentRepository` | Segment summaries with their guided pauses and feedback. |
| `BaselineRepository` | `DataStoreBaselineRepository` | Personal resting baseline. |
| `LearningRepository` | `RoomLearningRepository` | Learned profile per activity and learning progress. |
| `PauseResponseRepository` | `DataStorePauseResponseRepository` | Which nudges you accept or decline; feeds the nudge sensitivity. |
| `MascotRepository` | `DataStoreMascotRepository` | The mascot's name. |
| `VoiceConsentRepository` | `DataStoreVoiceConsentRepository` | Consent to use the system voice recognizer. |

## What the domain computes

| `core-domain` package | What it does |
|---|---|
| `features`, `sensing`, `state` | Signal windows, classification (rules or TFLite) and state smoothing. |
| `session` | Session start, tracking and end; pause suggestions and haptic signals. |
| `pause` | `PauseAdvisor` decides when to suggest a pause and `GuidedPause` records guided breathing and its effect. |
| `learning`, `profile` | Per-activity profile, nudge sensitivity, best time slot, suggested activity and the discovery of when you rate your sessions best. |
| `energy`, `score`, `summary` | Estimated energy, broken-down daily score and session and day summaries. |
| `cycles` | Focus-cycle detection with a periodogram; only reported with confidence. |
| `voice` | Interpreting what you say (`IntentParser`, `ActivityMatcher`) and the fallback path to the list. |

## UI (`app-wear/ui`)

One package per screen (`home`, `session`, `pause`, `feedback`, `summary`, `sessionsummary`,
`newactivity`, `voice`, `ambient`, `debug`), plus `components` (energy silhouette, state
indicators, buttons), `mascot` (Lumi drawn in Canvas) and `theme` (Aurora colors, Lexend typography).
`navigation/Screen.kt` puts the same background on every screen. The summaries are vertical
pages (`VerticalPages`). Design and product decisions are in
[`decisions.md`](decisions.md).

## Voice

`SpeechInput` abstracts the recognizer: `RecognizerSpeechInput` uses the system one and `TextSpeechInput`
(debug only) replaces it with typed text on the emulator, which has no recognizer. Any failure
leads to the activity list. Privacy details are in the [README](../../README.md).
